# Interfaces — everything externally reachable

One gin engine on one port (`:3333` by default) carries all of it. Anything you add here
is reachable by anyone who can reach the port; read [auth.md](auth.md) before adding a
route.

## How a route gets mounted

A subsystem contributes an `httpserver.Option` — a `Key()` and an `Apply(*gin.Engine)` —
to the `http_server_options` value group. `httpserver.Server` collects the group, filters
it against `Config.Options` (`["*"]` by default, or an explicit list), **sorts by key**,
and applies each in turn.

The sort is load-bearing: `"auth"` sorts before `"graphql"`, `"import"` and `"torznab"`,
which guarantees the identity middleware is mounted before any handler that reads an
identity back out.

| Key          | Package                         | Route(s)                                                              |
| ------------ | ------------------------------- | --------------------------------------------------------------------- |
| `auth`       | `internal/auth/http_auth`       | middleware only, no route                                             |
| `graphql`    | `internal/gql/httpserver`       | `POST /graphql`; `GET /graphql` (playground) only when enabled        |
| `import`     | `internal/importer/httpserver`  | `POST /import`                                                        |
| `prometheus` | `internal/telemetry/httpserver` | `/metrics`                                                            |
| `pprof`      | `internal/telemetry/httpserver` | `/debug/pprof/*`                                                      |
| `static`     | `internal/httpserver/static`    | a configured directory, default `/ui`; off unless `static.dir` is set |
| `torznab`    | `internal/torznab/httpserver`   | `/torznab/*`                                                          |

Before the options run, `httpserver.NewEngine` sets `SetTrustedProxies(config.TrustedProxies)`
— empty by default, meaning `X-Forwarded-For` is not believed and `ClientIP()` is the real
peer. Gin's own default is to trust every proxy, which would make the login throttle
keyed by a value the attacker writes. Then `httpserver.Middleware` installs the zap
request logger and a **custom recovery** (not `gin.Recovery`, which prints the request
line verbatim including a Torznab `apikey`).

## GraphQL

- Schema: `graphql/schema/*.graphqls`. Example client operations: `graphql/queries/`,
  `graphql/mutations/`.
- `internal/gql/gql.gen.go` (~24k lines) is generated by `task gen-gql`. Never edit it.
- Resolvers: `internal/gql/resolvers/`. Models the resolvers return:
  `internal/gql/gqlmodel/`.
- Authorization is the `@auth(object:, action:)` directive on the top-level `Query` and
  `Mutation` fields. Every field there carries one; sub-fields inherit by virtue of their
  namespace field being gated. The set of directives in the schema _is_ the registered set
  of GraphQL object actions — `gqlfx` extracts them from the schema AST rather than
  restating them.
- The handler accepts JSON POST and automatic persisted queries. Introspection and the
  playground at `GET /graphql` are each gated on a `graphql.*` config key and **default to
  off**; with the playground off that route is not registered, so the path 404s. Multipart
  and WebSocket transports are disabled because the schema has neither uploads nor
  subscriptions. A valid browser-cookie mutation must
  pass the same-origin check described in [auth.md](auth.md) before any resolver runs.

Adding a field means: edit the schema, `task gen-gql`, implement in `resolvers/`, then
regenerate external clients in their own projects.

## Torznab

`internal/torznab` is the \*arr integration surface — what Sonarr, Radarr and Prowlarr
talk to. `interface.go` defines the operations, `adapter/` maps a Torznab search onto the
database search, `categories.gen.go` maps Newznab categories, and `httpserver/` is the
gin handler.

Its authorization is deliberately separate from everything else
([`torznab/httpserver/auth.go`](../../internal/torznab/httpserver/auth.go)): only the
`apikey` query parameter or `X-Api-Key` header counts, the global bearer middleware's
identity is ignored, and a JWT presented in the apikey slot is refused. Failures answer
with Newznab error code 100 as an XML body, because \*arr clients parse it. The reasoning
is in the file's comments and is worth reading before touching it.

## Import

`POST /import` streams newline-delimited JSON into `internal/importer`. It writes
torrents, so it is guarded by `http_auth.Guard` against an `import` object action. `X-Import-Id`
names the import batch, which lands in `torrents_torrent_sources.import_id`.

It also requires `Content-Type: application/json`, answering anything else with 415 before
reading a byte of the body. That is a CORS property rather than a parsing one: `text/plain`,
`multipart/form-data` and `application/x-www-form-urlencoded` are the media types that make
a cross-origin POST a _simple request_, sent with no preflight, so a page the operator
visits could write to this endpoint without the browser ever consulting `allowed_origins`.
Refusing them forces the preflight that the origin policy gets to answer.

The import owns a context derived from the request's, and cancelling it - a client
disconnecting mid-stream, or a shutdown - ends the buffering loop and makes any waiting
`Import` return `ErrImportClosed`. That has to hold: `http.Server.Shutdown` waits for
in-flight requests, so an import that cannot be interrupted hangs the process rather than
just itself.

## Telemetry and health

- `/metrics` — Prometheus. Collectors are contributed to the `prometheus_collectors` group
  from all over the tree (`dht_crawler.persisted_total`, queue depth, torrent counts).
- `/debug/pprof/*` — guarded like the importer.
- `internal/health` is _not_ an HTTP route; checks are exposed through the GraphQL
  `health` query, which the baseline permission set grants to everyone so clients
  can check health before login.

## Separately served UI

The fork ships no embedded frontend. Set `http_server.static.dir` to a built UI on disk
and it is served at `http_server.static.path` (default `/ui`), on the API origin. Unknown
paths fall back to `index.html`. `/webui` is available as a mount path; `/` remains
refused because its wildcard would conflict with the API routes. No default route
redirects the root. Remove `webui` from any explicit `http_server.options` list when
upgrading: it is no longer a registered component.

The mount sends `Cache-Control: no-store`, so a browser observes deployments replacing
stable filenames on disk. A reverse proxy can instead serve the UI and API together.

## CORS

`http_server.cors.allowed_origins` defaults to an empty list, which withholds CORS
permission. Same-origin browser clients and non-browser API clients continue to work.
Cross-origin browser deployments must explicitly list their UI origins; `['*']` opts
back into public cross-origin reads. The wrapper overrides the CORS library's empty-list
allow-all behavior with a deny callback.

The default allowed headers are `Content-Type`, `Authorization`, `X-Api-Key` and
`X-Import-Id`; debug logging is off. See [docs/auth.md](../auth.md) for deployment guidance.
