## Treat it as a patch source, not a base

The fork **converted the entire tree to CRLF line endings**. Raw diff against upstream
reads as 507 Go files / +77,347 / −72,453. Normalized with `-w --ignore-cr-at-eol` the
real change is **65 files / +4,920 / −26**.

Basing on it means every file in the repo permanently conflicts with upstream and
with every other fork. Treat it as a **source of patches**, applying diffs rather than
cherry-picking commits:

```bash
git diff -w --ignore-cr-at-eol upstream/main o51r15/main -- internal/prowlarr | git apply -3
```

The upside: because the real diff is +4,920/−26, it is **almost entirely additive** —
new fx modules, barely any edits to existing code. That makes it unusually easy to
take piecemeal.

## What it adds

### DHT / crawler reliability — _highest value_

| Change                                                                   | Files                                 |
| ------------------------------------------------------------------------ | ------------------------------------- |
| Global concurrent query semaphore capping in-flight UDP operations       | `protocol/dht/server/`                |
| `ReseedBootstrapNodesInterval` wired from config + ktable health monitor | `dhtcrawler/bootstrap.go` (new)       |
| Queue backpressure valve preventing unbounded `queue_jobs` growth        | `queue/server/server.go`, `importer/` |
| Padding-aware file threshold using `savedCount`                          | `dhtcrawler/persist.go`               |
| Dropped `router.bittorrent.cloud` (fails DNS through VPN/gluetun)        | `dhtcrawler/config.go`                |

### Metadata sources

### Prowlarr + RSS

- `internal/dbtrim` — retention worker for trimming the database.
- Migration `00023` — index on `torrents_torrent_sources.source`. **Renumber on merge.**

### Build / ops

mirror workflow, tuned docker-compose with Postgres settings and resource limits, a

Mostly deployment opinion specific to their setup — read, don't take wholesale.

## Assessment

The most _useful_ fork on the list and genuinely current, but the CRLF conversion makes
it a patch source rather than a base. The DHT reliability fixes and the `queue_jobs`
index are the parts to take first — they address real production problems and are small.

The repo also carries `ROADMAP.md` and `CHANGELOG.md` documenting their diagnostic
analysis, worth reading for the problem descriptions even where you don't take the fix.
